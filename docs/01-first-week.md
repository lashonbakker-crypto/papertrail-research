# 第一次做科研：7 天，每天留下一个可检查的小成果

建议每天 30–60 分钟。这是工具和科研过程的入门安排，不是发表论文或保研成绩承诺。

| 天 | 具体动作 | 当天完成的证据 |
|---|---|---|
| 1 | 按 README 跑 `demo`，打开报告；故意加入未知引用，再删掉 | 你能解释退出码 0/2 和一条 `missing_reference` |
| 2 | 在 `manuscript.md` 找 C1；打开 RAG 背景文献的摘要，核对那句话 | 一张用自己的话写的证据卡；记下只读了摘要的范围 |
| 3 | 打开 `artifacts/demo.json`，找到 q01 的排名 | 你能说清相关文档、rank、MRR 和 Recall@1 的含义 |
| 4 | 阅读 `papertrail/experiment.py`，在新目录重跑 demo | 逐查询结果一致；你能指出同分处理规则 |
| 5 | 选一个与你课程/课题有关的小问题，创建空白项目，导入 3 篇参考文献 | `project.json` 中的问题可以检验；3 条完整的元数据 |
| 6 | 真正阅读其中一篇，在证据卡记下章节、适用条件、自己的疑问 | 至少 2 张不是复制摘要的笔记；你能区分作者结论与自己猜测 |
| 7 | 用组会模板讲一次：做了什么、证据在哪里、哪里还不确定 | 一份 1 页进展记录；下一周一个小实验计划 |

## 三个先学会的概念

**引用键**：像文献的本地名字。正文里的 `[@lewis2020]` 对应 `references.json` 中的 `key`。拼错就接不上。

**证据定位**：你不是只说“这篇论文讲过”，而是记下“在摘要/方法第 2 节/第 4 页哪一段”。只看过摘要，就按摘要记录，不假装读完全文。

**可复现记录**：别人拿到同一份输入、同一段实现和命令，可以检查如何得到结果。它仍不证明研究问题重要、数据真实或方法最好。

## 第 3 天的手算练习

一条查询的正确文档排第一：倒数排名是 `1/1=1`；排第二则是 `1/2=0.5`。MRR 是这些倒数排名的平均值。
在本例每条查询只有一个相关文档，因此 Recall@1 表示有多少查询把它放在第一位，Recall@3 表示有多少放在前三位。

两种方法在演示语料上都得到 1.0。这个结果只能说明例子简单，不能用来证明复杂方法没有价值，更不能写成“已达到生产级效果”。

## 你可以怎样继续

先独立解释一个简单基线，再接触更复杂的模型。保留尚未用于选方法的新数据，用于后续评价。把失败例和范围限制写下来，比只展示一个漂亮分数更能说明你理解过程。
