# 把真实科研工作整理进组会和申请材料

保研材料的要求取决于学校、院系、年份和具体项目；这里提供科研过程的组织方式，不代替当年的正式规定。

## 应该能回答的五个问题

| 问题 | 对应记录 |
|---|---|
| 你解决什么小问题？ | project.json 的 question，说明对象、指标和范围 |
| 你真的读了什么？ | 自己写的证据卡，能现场定位原文并解释条件 |
| 你亲自做了哪部分？ | 贡献日志中的具体操作和可核对提交，区分自己、队友、AI 的贡献 |
| 结果从哪里来？ | 原始输出、输入数据版本、实现版本、复现命令、失败例 |
| 现在还不知道什么？ | 不确定性、切分限制、尚未做的实验和下一步 |

## 一个可填写的描述结构

“围绕【具体问题】，我负责【真实个人工作】。以【明确基线】为比较对象，在【数据版本与评价范围】上得到【实际结果】。我用【具体检查】核对了结果；目前的局限是【真实限制】。”

这是填写结构，括号必须由实际工作替换。只运行了本仓库 demo，可以说自己练习了证据和实验管理；不能把背景论文、AI 生成的实现或教学分数算作自己的原创研究。

## 保留的材料

原始实验输出和代码提交、经许可的数据、自己的阅读笔记、成员分工、AI 使用记录、导师建议和修改结果。
推荐用 [contribution-log.md](../templates/contribution-log.md) 和 [advisor-update.md](../templates/advisor-update.md) 每周记录。

个人申请文件、成绩、未公开课题材料和授权受限数据保留在自己的工作目录。公开仓库只放你有权分享的去标识化材料。
